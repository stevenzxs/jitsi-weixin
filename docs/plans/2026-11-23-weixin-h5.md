# 微信/企业微信 H5 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 新增独立免安装访客入会网页，复用指定 Jitsi，不改变现有客户端入口。

**Architecture:** 原生 ES Modules 静态应用，依赖指定同源 Jitsi external_api.js。运行配置限定受信任 origin，不接受查询参数覆盖服务地址，不在前端生成 JWT。独立 config Git 库负责部署契约和云端校验入口。

**Tech Stack:** HTML、CSS、浏览器 JavaScript、Node 内建 test/assert/http，无第三方运行依赖。

## Task 1: 核心输入和环境契约
- 新建 tests/core.test.mjs，验证严格九位会议号、重复参数拒绝、主题长度、HTTPS/URL 限制、能力检测和错误翻译。
- 执行 npm test，记录 RED；实现 src/core.mjs，重新执行记录 GREEN。

## Task 2: 入会生命周期
- 新建 tests/session.test.mjs，先验证无自动采集、昵称必填、媒体开关、错误转交、离会清理和重入保护；运行 RED。
- 实现 src/session.mjs；运行 GREEN。External API 替身不替代真实媒体。

## Task 3: 移动页面
- 新建 index.html、src/app.mjs、src/style.css、runtime-config.example.json。
- 提供输入、检测、加入、离会及失败恢复；使用 textContent 不注入外来 HTML。每次加入由明确点击触发，Jitsi 自己申请设备权限，避免双重采集。
- npm run dev 后浏览器检查移动/桌面布局及异常路径；不连接现有真实会议。

## Task 4: 配置边界和交付
- 独立 config/ Git：公开运行配置样例、部署前提、仅手动静态校验工作流及 SKILL.md；不触发产品发布。
- 正式 rN 分配和首次基线缺失时阻断发布，不实现临时计数假装合规。
- 两库提交推送合 main，核验远端，更新唯一台账。无 SSH/证书替换/Actions 调度。

## Acceptance
- npm test 通过；本地浏览器页面和错误路径通过。
- IP 公开证书、自动续期、可信入口同源路由、会议访客策略、TURN/JVB、Android/iOS 微信和企业微信均待真实验收。
